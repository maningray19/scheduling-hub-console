Facilitator Command Center Booking continuity guide

When the shared calendar is unavailable

Keep the client request. Confirm the time safely.

Sales can keep taking interview requests in their own company’s existing client or lead records. Aira, or the coordinator appointed to cover her, checks the shared availability before anyone promises a time.

A request is not a confirmed booking. If availability across both companies cannot be verified, keep the requested time pending. Do not book around the shared calendar or promise the same slot to two clients.

This guide opens without signing in or loading the calendar. It describes a manual process available now. An automatic backup intake queue in the company portals is still being evaluated; do not assume one exists.

Sales team

Take the request without losing it

  1. Use the existing company record

    Open the client or lead in the company that owns the request. First check for an existing booking or pending request for that interview. Keep client details inside that company’s approved record.

  2. Record one unique request reference

    Use one request reference in that existing record. Keep the same reference for every follow-up, correction and recovery check. Do not start a second request because a screen timed out.

  3. Capture the requested time and alternatives

    Record the requested date and time in Dubai time, the interview duration, and alternative times the client can attend. Mark the request Requested.

  4. Ask the coordinator to check it

    Contact Aira through the company’s approved channel with the request reference and a link to the existing record. Mark it Awaiting confirmation. Tell the client: “We have recorded your request. Your interview time is awaiting confirmation.”

  5. Confirm only after the availability check

    Wait for the coordinator’s explicit confirmation of the exact slot. Only the owning company sends its client confirmation, once. If the slot cannot be confirmed, offer an alternative and keep the same request reference.

Aira and appointed cover

Protect the shared interview time

  1. Establish who is coordinating

    Management appoints one active coordinator and a backup person to cover absence. Make the handover explicit so both people do not confirm different requests for the same slot.

  2. Check both companies before confirming

    Review existing bookings and pending requests from both companies through approved access. Check interview hours, breaks, duration and any time already confirmed. Do not share one company’s client information with the other.

  3. Keep uncertain availability pending

    If current shared availability cannot be verified, do not confirm the time. Keep the request Awaiting confirmation and tell sales what is still being checked.

  4. Record the decision against the same request

    When availability is verified, record the exact Dubai slot, the coordinator who checked it, and the time of that check in the owning company’s record. Mark Confirmed only after the booking has been verified or safely entered through the approved booking process.

  5. Give the outage an owner

    Management names the incident owner, who tracks the service problem and tells the teams when recovery has been verified. The coordinator tracks pending requests until each is confirmed or needs correction.

Use the same four states

Write the state against the request in its existing company record. These are manual receipt states; this guide does not save or update a booking.

Requested
The request and alternatives are recorded. No interview time has been promised.
Awaiting confirmation
The coordinator is checking availability. Sales keeps the client informed without promising a slot.
Confirmed
The exact slot and existing or newly created booking have been checked. The owning company sends one confirmation.
Needs correction
A detail, duplicate or time conflict needs resolving. Record the reason and next action under the same reference.

When the shared calendar returns

Reconcile first. Create only what is missing.

  1. Verify recovery before clearing requests

    The incident owner confirms that the calendar and booking checks are working. A successful page load alone does not prove that a booking can be confirmed.

  2. Match each request to existing records

    Use the same request reference, owning client or lead record, and requested slot to check both the company record and shared calendar. A lost response may have left an existing booking. Do not create another one to find out.

  3. Resolve differences before proceeding

    If records disagree or more than one booking appears, mark Needs correction and ask the coordinator to resolve it. Keep the original request and booking references.

  4. Complete one booking or synchronization

    If no booking exists and availability has been checked, the owning company creates the booking once through its approved process. If the booking already exists, verify or synchronize that same booking instead. Confirm the final status, then send only the owning company’s one client confirmation.
